## 4. Defects Found

### BUG-001 — Dark Mode: `--ink-3` Fails WCAG AA Contrast (Major)

**Title:** Dark mode `--ink-3` token achieves only 3.20:1 contrast on canvas and 2.99:1 on surface — fails WCAG AA for normal text (requires 4.5:1)

**Environment:**
- OS: Windows 11 Pro
- Browser: Chromium (Claude Desktop in-app browser)
- Test environment: local dev server (`npm run dev`, port 3000)
- Commit: current HEAD (branch main)

**Reproduction Status:** Reproducible

**Steps to Reproduce:**
1. Load the application with `data-theme="dark"` set on `<html>` (click the theme toggle or run `document.documentElement.setAttribute('data-theme','dark')` in browser console)
2. Navigate to `/dashboard` or the `/qa-verify` test fixture
3. Inspect secondary text elements: constituent count ("12 stocks"), "Sector map" provenance label, no-trigger text, empty state description paragraph

**Expected Behavior:**
All text elements pass WCAG AA — minimum 4.5:1 contrast ratio for normal text (≤18pt), per T-ARJ-02 AC: "all text meets WCAG AA contrast."

**Actual Behavior:**
`--ink-3` dark mode value `#6B6560` achieves:
- 3.20:1 against `--canvas: #17140F` (fails AA — minimum 4.5:1 for normal text)
- 2.99:1 against `--surface: #1E1B16` (fails AA — also fails the 3.0:1 large-text threshold)

Affected elements (all use `var(--ink-3)` at ≤14px font size):
- SectorCard: constituent count sub-label ("12 stocks") — `var(--text-sm)` = 12px
- SectorCard: "Sector map" provenance label — `var(--text-sm)` = 12px
- TriggerSummary: no-trigger italic text — `var(--text-ui)` = 14px
- EmptyState: description paragraph — `var(--text-ui)` = 14px
- RankingTabs: "Showing top N of M sectors" footer — `var(--text-sm)` = 12px

**Evidence:**
JavaScript contrast calculation in-browser:
```
--ink-3 (#6B6560) on --canvas (#17140F): 3.20:1
--ink-3 (#6B6560) on --surface (#1E1B16): 2.99:1
WCAG AA threshold for normal text: 4.5:1
```

**Severity:** Major
- T-ARJ-02 AC explicitly requires WCAG AA in dark mode
- Plan note says "obvious failures should be fixed"
- 3.20:1 vs 4.5:1 required is an obvious failure (30% below threshold)
- Affects all secondary text in the dashboard in dark mode

**Fix owner:** Arjun — update `--ink-3` in `[data-theme="dark"]` block of `frontend/styles/tokens.css` to a lighter value that achieves ≥4.5:1 against `#17140F`. Starting point: `#8A8580` or lighter achieves ~4.5:1; verify with WCAG contrast checker.

### BUG-002 — Test Mock Content Uses Wrong JSON Keys (Minor)

**Title:** `test_reports_api.py` mock report content uses `price_rankings`/`volume_rankings` keys but the actual `run_daily_briefing` pipeline produces `rankings_price`/`rankings_volume`; the provenance test validates mock data, not the real API contract

**Environment:**
- OS: Windows 11 Pro
- Test environment: local pytest
- File: `backend/tests/test_reports_api.py`

**Reproduction Status:** Reproducible

**Steps to Reproduce:**
1. Inspect `_make_report()` in `test_reports_api.py:45`: default content uses `"price_rankings"` key
2. Inspect `test_returns_content_with_provenance_fields` at line 343: mock content uses `price_rankings`/`volume_rankings`/`triggers`; asserts on `body["content"]["price_rankings"][0]`
3. Inspect `_assemble_content()` in `backend/app/jobs/daily_briefing.py:147`: actual pipeline produces `rankings_price`/`rankings_volume`/`triggers`
4. Inspect `frontend/components/dashboard/types.ts:26`: frontend expects `rankings_price`/`rankings_volume`

**Expected Behavior:**
Test mock content keys match the actual pipeline output format. The provenance test validates the real contract, not a divergent mock format.

**Actual Behavior:**
Mock data in `test_reports_api.py` uses `price_rankings` (matches EXP-20260926-001 spec §5.3) but the actual pipeline (`daily_briefing.py`) produces `rankings_price` (matches the frontend type definition). Tests pass because they validate their own mock data — but the test does NOT verify that a real pipeline-produced report can be correctly consumed by the frontend.

**Evidence:**
- `test_reports_api.py:45`: `{"date": str(trading_date), "price_rankings": []}` — wrong key
- `daily_briefing.py:149`: `"rankings_price": [...]` — correct runtime key
- `types.ts:26`: `rankings_price: SectorRankItem[]` — frontend expects `rankings_price`

**Severity:** Minor — the runtime path (pipeline → API → frontend) works correctly end-to-end because all three agree on `rankings_price`. This is a test quality defect, not a runtime bug. However, it creates a false spec artifact and is a maintenance hazard.

**Fix owner:** Bhima — update `_make_report()` default content and the provenance test mock content in `test_reports_api.py` to use `rankings_price`/`rankings_volume`. Also update EXP-20260926-001 §5.3 to reflect the implemented key names. No production code change required.

## 5. Exploratory Testing Notes

**Auth guard behaviour:** Confirmed that navigating to `/dashboard` unauthenticated redirects to `/login` (Page title changes to "Sign in — Viveka", URL becomes `/login`). All three report API endpoints (`/api/v1/reports`, `/api/v1/reports/{id}`, `/api/v1/reports/latest`) return HTTP 401 when no session cookie is present (verified by 3 unit tests).

**Volume multiplier format:** `234.0 × 100 → 2.34×`, `178.5 × 100 → 1.78×` (floating-point rounding consistent). Format renders `X.XX×` as specified.

**Synthetic exchange URLs:** `nse://` and `bse://` synthetic URLs from the news aggregator are rendered verbatim by `_friendlyDomain()` (detected via `!url.startsWith("http")` guard). Links with these schemes will not navigate but render correctly as text. This is expected for the test environment; in production, exchange announcements will have real HTTPS URLs for attachments or BSE/NSE synthetic identifiers for the `UNIQUE(url)` deduplication constraint. These synthetic URLs are internal identifiers, not user-facing links. **No defect filed — intended behaviour.**

**job_executions CHECK constraint:** Migration a0013 correctly fixes the `'success'` → `'completed'` discrepancy. The scheduler writes `status='completed'` on success, which now matches the CHECK constraint. Verified via code inspection; live DB verification deferred to T-NAK-01.

**LLM cost guard:** Unit tests confirm `COST_GUARD_PCT = 0.90` (90% of ceiling). When monthly spend ≥ ₹450, all LLM calls are skipped and all trigger results are set to NO_TRIGGER_TEXT. Rankings continue to publish regardless. Verified by 3 unit tests including `test_high_spend_skips_all_llm_calls`.

**Staleness check ordering:** `check_data_freshness` returns `is_fresh=True` on non-trading days without querying the DB. This is correctly placed before the OHLCV fetch step in `run_daily_briefing`. The staleness guard fires on empty price_data for a trading day and returns `BriefingResult(skipped=True)`. Verified by 11 unit tests.

**ARIA landmark structure (dashboard):**
- ✓ `role="tablist"` with `aria-label="Ranking type"`
- ✓ `role="tab"` with `aria-selected`, `aria-controls` on each tab button
- ✓ `role="tabpanel"` with `aria-labelledby`
- ✓ Collapsed sector card buttons have `aria-expanded="false"`, `aria-controls`
- ✓ Expanded panels have `role="region"`, `aria-labelledby` pointing to the header button
- ✓ Loading state has `role="status"`, `aria-label="Loading briefing"`, `aria-live="polite"`
- ✓ Empty state has `role="status"`, `aria-live="polite"`
- ✓ Error state has `role="alert"`
- ✓ News URL links have `target="_blank"`, `rel="noopener noreferrer"`

**`test_fetchers.py` exclusion:** This file is excluded from all test runs on this machine due to a pre-existing DLL block on `pandas._libs.testing` (Windows Application Control policy). This is a machine-specific environmental issue documented in Phase 0 QA (QA-RPT-20260926-001). The 390 remaining tests cover all functional behaviour. This exclusion was accepted by the team in Phase 0.
